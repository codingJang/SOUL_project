# Platform Compatibility: macOS → Linux Deployment

## The Problem

When developing on **macOS** and deploying to **Railway's Linux servers**, several compatibility issues arise:

### 1. **Platform-Specific Hashes** 
- `requirements.txt` generated by `uv export` contains SHA256 hashes
- These hashes are specific to macOS wheels
- Linux servers need different wheel versions with different hashes
- **Result**: `Hash mismatch` errors during pip install

### 2. **Binary Wheel Differences**
- Packages like PyTorch, NumPy, SciPy have different binaries for different platforms
- macOS: `.whl` files compiled for Darwin (x86_64 or arm64)
- Linux: `.whl` files compiled for Linux x86_64
- **Result**: Installation failures or runtime errors

### 3. **CUDA Dependencies**
- PyTorch includes NVIDIA CUDA libraries for GPU acceleration
- These are marked `platform_machine == 'x86_64' and sys_platform == 'linux'`
- **Good news**: This actually helps Railway deployment since it runs Linux x86_64!

## The Solution

### ✅ **Dual Requirements Files**

1. **`requirements.txt`** (with hashes)
   - For local development and exact reproducibility
   - Contains platform-specific hashes for security
   - Use for local `uv sync` operations

2. **`requirements-railway.txt`** (without hashes)
   - For Railway deployment
   - No platform-specific hashes
   - Allows pip to select appropriate wheels for Linux
   - Generated with: `uv export --format requirements-txt --no-hashes`

### ✅ **Updated Deployment Configuration**

**Procfile:**
```
web: pip install -r requirements-railway.txt && uvicorn src.webapp:app --host 0.0.0.0 --port $PORT
```

**railway.json:**
```json
{
  "build": {
    "builder": "NIXPACKS",
    "buildCommand": "pip install -r requirements-railway.txt"
  },
  "deploy": {
    "startCommand": "uvicorn src.webapp:app --host 0.0.0.0 --port $PORT"
  }
}
```

## Expected Behavior on Railway

1. **Build Phase**: Railway will install from `requirements-railway.txt`
2. **Dependency Resolution**: pip will automatically select Linux-compatible wheels
3. **CUDA Libraries**: Will install correctly for potential GPU usage
4. **Runtime**: Your FastAPI app will run with Linux-optimized dependencies

## Troubleshooting

If you encounter issues:

1. **Hash Mismatch Error**:
   ```bash
   # Regenerate Railway requirements
   uv export --format requirements-txt --no-hashes --output-file requirements-railway.txt
   ```

2. **Missing Dependencies**:
   ```bash
   # Check what's in your Railway requirements
   cat requirements-railway.txt | grep -i "missing-package"
   ```

3. **Import Errors**:
   - Usually caused by missing system libraries
   - Railway's NIXPACKS builder should handle most cases
   - Check Railway build logs for system dependency issues
